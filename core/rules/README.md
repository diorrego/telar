# rules

**Stage 1, workshop. Trust pyramid layer 5: prose rules. The last resort.**

Guidance that requires judgment and cannot be expressed as a check, a verification or a skill. This is what the core contributes to a target repository's `CLAUDE.md` and `AGENTS.md`.

## Belongs here

- Conventions that need judgment: when to stop and ask, how to scope a change, how to report to the owner.
- Context through structure: what each top-level directory of a target is for.

## Does not belong here

- Anything enforceable. Move it down the pyramid: prose drifts, agents over-apply it as a hard rule, and it gives them room to justify the wrong thing.

## Contract

- Each rule says why no check, verification or skill could express it.
- Rules are short, specific and positive ("do X", not "never forget Y").
- A rule that has to be repeated in a correction is a candidate to become a check.
- This folder should shrink over time as rules turn into checks. Its size is a health metric.
